# TikTok post downloads — 0.1.37

Alcydeo recognizes the currently selected public TikTok post from the page's already loaded native JSON, including `__UNIVERSAL_DATA_FOR_REHYDRATION__` and legacy SIGI data. A `blob:` player no longer prevents discovery. The real description supplies the filename, and native pixel dimensions, sizes and codecs supply quality choices on one card. AVC is preferred at equal resolution. The static website-login animation is excluded on TikTok pages.

The supplied post reproduces both failures of the earlier build: the login animation appeared under the generic page title while the video was playing through a Blob, and extension-origin requests to the actual CDN were refused. The same original URLs work with the original TikTok frame's browser-managed origin/referrer. No signature is altered and no authentication/header workaround is added.

## Download path

Source sampling and the actual transfer run in the original authorized TikTok frame, using packaged original code and normal browser fetch/CORS. A four-kilobyte sample checks availability and detects HTML/small-file errors. After the explicit Download action, the file streams into the existing manager and Worker pipeline, through messages capped at 256 KiB, with progressive writes to extension OPFS. It is not buffered as a complete media file in JavaScript memory, reencoded, or uploaded to an Alcydeo server. Structure, track, duration and first/last packet checks precede automatic Chrome saving. Since 0.1.47, local browser playback does not gate the saving of an already validated output. Saving preferences and original-title naming remain respected.

Keep the TikTok tab on the selected post and keep the manager open until saving completes; the popup may close. Pause/cancel abort the contextual fetch and discard uncommitted output. Resume starts that file from the beginning, without mixing partial versions. If the original tab has been closed, navigate to the post and detect it again. Existing verified results can be saved without fetching TikTok again. Closing the manager stops its Worker; abandoned page readers expire after 30 seconds without use.

Native metadata URLs remain unchanged. No cookie values are read/copied, no custom Origin/Referer is supplied, no signature, challenge or token is generated, and no remote executable is evaluated. The extension asks for no new manifest permission, DNR rule, debugger or companion. Its existing site/asset host permissions and blacklist are checked before source operations. A same-context 401/403 remains an explicit source refusal; transient network uncertainty stays unconfirmed instead of silently removing a known catalog entry.

## Bounds and limitations

- Read only the exact selected post ID; stale data after client navigation never becomes the next post's catalog. If TikTok does not refresh its JSON when scrolling, reload the selected post's page. The feed, photo slideshows, live streams, private/restricted posts and every regional layout are not universally supported.
- The current reader has a shared 8 MiB parsing budget per call and retains at most 24 native formats. The observer examines at most 128 script nodes and captures at most 32 native blocks per mutation batch. Unexpected hosts, credentials in URLs, non-HTTPS addresses, known video-only HEVC tracks and custom VVC formats are refused.
- Samples use an eight-second bound, transfer headers fifteen seconds, idle readers thirty seconds and Worker RPC replies thirty-five seconds. There is at most one outstanding chunk per transfer and two reader slots per source frame. A late response after cancellation cannot commit or export a file.
- Interrupted contextual downloads restart. Multi-part settings continue applying to compatible ordinary direct downloads; this source-frame path uses one sequential body and does not invent range-resume support.
- The original 0.1.37 check validates H.264/AAC for its supplied post; its HEVC variants had prefix evidence only. The later complete HEVC result for the additional post is documented separately below. Large/long TikTok files, browser/process shutdown, physical Cast and original-CDN preview/receiver access remain separate checks. A receiver may not have the originating page's source access; saved-file tools keep their existing limits.
